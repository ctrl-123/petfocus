## ⚠️ 先读这一节：能力边界（如实说明）

**浏览器没有权限结束其他进程、也无法阻止你打开微信或游戏。这是浏览器的安全规定，不是实现缺陷。**

因此本项目的约束能力分两层，界面上会如实标注，**不会假装已经拦截**：

| 模式 | 前提 | 能做到 | 做不到 |
|---|---|---|---|
| **软约束** `[Web]` | 打开网页即可 | 强制全屏接管 · 检测你切走窗口并累计违规 · 违规超过 30 秒暂停计时 · 结算时按违规占比扣减收益 · 退出全屏会被记录并有限重试 · 到点唤回 · 打开时补偿提示错过的专注 | 阻止你启动其他程序；阻止你用 `Alt+F4` / 任务管理器关掉页面 |
| **硬约束** `[原生]` | 额外安装可选的 **Windows 桌面增强包** | 真实结束/挂起非白名单进程 · 到点由常驻进程强制唤出 · 主进程未运行时自动降级为软约束 | 仅 Windows · 需管理员权限 · 仅承诺桌面 Chrome/Edge · 未签名会被 SmartScreen 提示 |

移动端（iOS/Android 浏览器）**不支持任何拦截能力**，仅保留待办、计时、统计、宠物与专项模块。

> 这是本项目的一个**有意架构选择**：把跨不过去的平台边界，用一个最小化的原生伴侣进程补上。
> 完整裁决过程见 [需求研究报告第 5 节](docs/research/01-需求研究报告.md) 与 [技术设计第 12.1 节](docs/03-技术设计文档.md)。

## ✨ 产品一句话与六大模块

**定位**：给「硬核拦截工具」装上「情感陪伴」。市面上的产品要么能拦但冰冷（Cold Turkey / Freedom），要么温暖但完全不拦（Finch / Habitica）——本项目补的是这个空白区。

| 模块 | 一句话 |
|---|---|
| 🎯 **专注模式** | 到了待办时间自动接管屏幕；非白名单应用不可用；每日 1 次 + 每月累计 5 次退出机会，用完还有出口，但要付代价 |
| ✅ **待办集** | 每天首次打开强制花 30 秒写「时间 + 事件」，之后当天不再打扰；首页展示，到点自动进入专注；完成即发金币与奖励话术 |
| 🔒 **锁机** | 没有待办时主动把自己锁起来；按时长发金币（12 币/小时）；每月 5 次退出机会，与专注配额独立 |
| 📊 **统计** | 今日/本周/本月：专注时长、事件明细、**专注日历热力图**（空格子刻意做得刺眼）、趋势/时段/占比三类图表 |
| 🧩 **专项模块** | 侧边栏可自定义。内置：健身打卡 · 饮食健康（含「今天吃什么」转盘 + 本地营养库优先的营养分析）· 记账理财（分类统计与预算） |
| 🐾 **养宠物** | Live2D 立绘宠物，点击有抚摸反应、会跟随视线、会饿会蔫但**永不死亡**；金币买食物与装扮，带独立商城 |

### 设计上的三个关键取舍

1. **惩罚只落在数字与宠物状态上，绝不落在语言上。** 结算文案禁止出现「你真懒」「又失败了」。
2. **宠物永不死亡、不离家出走。** 惩罚最重也只是「蔫 30 分钟」，可通过抚摸或 30 金币的食物恢复。
3. **配额式解除，而不是焊死出口。** 每天/每月留有限次数的无损退出通道——遇会议、上课、身体不适时不至于「一堵就砸墙」。另有「本次跳过」（不耗月配额，扣 10 币，每日 2 次）。

| Q9 | Live2D 模型 | **先用免费授权模型**，要求许可允许修改（换装必需）并完成强制署名；找不到则退 Rive / 序列帧。详见下方「许可与署名」 |

### 成本：月支出 0 元（硬性约束）

需求方明确要求低资金投入，所以「零成本运行」是**产品约束**，不是优化目标。已查证官方额度（2026-02-14）：

| 服务 | 免费额度 | 本项目实际用量 | 结论 |
|---|---|---|---|
| **Vercel Hobby** | 个人非商业项目免费 | 纯静态 PWA，几百 KB 资源 | **0 元** |
| **Supabase Free** | Edge Function **50 万次/月**、数据库 500 MB、出口 5 GB | 结算+AI 约 200–2,000 次/月；账本一年 < 10 MB | **0 元**（余量约 250 倍） |
| **Live2D Cubism SDK** | 个人（一般用户）**免 SDK 发布许可与费用**，免费模型素材可营利也可非营利使用 | — | **0 元** |
| **AI 营养估算** | 按量付费（唯一可能的变动成本） | 本地食物库优先，只有冷门菜才调 AI 且有缓存 | **0–3 元/月**；不配 Key 就是 **0** |
| **域名** | — | 可选，不买就用 `xxx.vercel.app` 免费子域 | **0 元** |
| **合计** | | | **¥0 / 月**（连域名都不买的情况下） |

已为此单列 [ADR-011 · 零成本运行](docs/03-技术设计文档.md)，并加了成本护栏：AI 调用「本地库优先 → 服务端缓存 → 每设备每日 ≤20 次 → 全局每日 ≤200 次」，超限自动回退手动录入。若将来某项功能必须付费才能实现，**优先降级功能而不是付费**。

⚠️ **一个必须知道的免费版限制**：Supabase 免费项目**连续 7 天不活动会被自动暂停**。这对「简历链接长期挂着」有影响。但因为架构是本地优先的——**业务数据本来就在你浏览器里**——所以项目即使被暂停，网页依然能正常打开、记待办、跑计时，只是金币结算会先排进「待确认」队列。我已在验收清单里加了「手动停用 Supabase 后网页仍可用」这条测试。

### 部署形态（Q8 的连带结论）

| 项 | 结论 |
|---|---|
| 前端 | **Vercel 免费版** |
| 后端 | **Supabase Edge Function 免费版**。不使用 Supabase Auth，不启用按用户 RLS |
| 后端职责 | 仅两件事：① 按设备 ID 结算金币/配额；② 代理 AI 营养估算（藏 API Key） |
| 上云内容 | 仅「设备 ID + 金币/配额账本」这类抽象计数，**不含任何用户内容** |
| 换设备 | 导出 / 导入 JSON |

> ⚠️ **关于「防作弊」的如实说明**：设备 ID 与签名密钥都由前端生成并保存在本机，**打开 DevTools 就能抄走并冒用**。这套机制挡得住「改系统时间」「改 localStorage」这类低成本作弊，但**不是防作弊系统**。本产品是自律工具，目标是让作弊比老实做事更麻烦，而不是不可能。这是被明确接受并公示的残余风险，详见 [技术设计 ADR-010](docs/03-技术设计文档.md)。

## 🧱 技术栈（规划，见 [技术设计第 2 节](docs/03-技术设计文档.md)）

**前端**：React 18 · TypeScript strict · Vite · Tailwind · Radix UI · Zustand · Dexie(IndexedDB) · Recharts · PixiJS + `pixi-live2d-display`
**后端**：**Supabase Edge Function（免费版）**，仅用于「按设备 ID 结算金币/配额」与「代理 AI 营养估算」。**不使用 Supabase Auth，不启用按用户 RLS**
**托管**：Vercel 免费版
**原生**：C# .NET 8 单文件 exe（本地 WebSocket，仅监听 `127.0.0.1`）
**测试**：Vitest（领域层覆盖率 ≥ 95%）· Testing Library · Playwright · 前端/服务端经济公式契约测试

**架构原则**：本地优先（业务数据只在本机）· 时钟不可信但自洽（单调时钟计时）· 状态可重建（崩溃可恢复）· 约束能力可降级（无原生则明确标注软约束）· 业务规则可测试（领域层零依赖）· 身份匿名（无账号，匿名设备 ID + 请求签名）
