## 1. 为什么这个 spike 必须先做

宠物要支持**换装**，而 Live2D 的免费模型里最常见的那几个**明文禁止修改设计**：

> 依据 [Live2D 样例数据使用条款](https://www.live2d.com/eula/live2d-sample-model-terms_en.html) 与
> [无偿提供素材使用授权协议 v1.6](https://www.live2d.com/eula/live2d-free-material-license-agreement_cn.html)：
>
> - **Hiyori Momose / Miara：不得对该角色设计做任何变更**
> - Shizuku：不得改名或改设置
> - Nito：必须保持头身比例
> - Mark-kun：不得改画成帅哥或戏剧化风格
> - 合作角色（Jin Natori、Tsumugi Harugasa）：**禁止营利目的**使用、修改、发布

也就是说：**教程里最常被抄的那个模型，恰好不能用于换装。**
如果不先验证就动手，会在 M5 后期发现换装功能无模型可用。

## 2. 判定标准（三条全部满足才可用）

| # | 标准 | 怎么验 |
|---|---|---|
| C1 | **许可允许修改**（换装必需） | 读模型配布页的利用条件；允许「改変」或为 CC0/CC-BY |
| C2 | **有可切换部件或皮肤** | 用 Cubism Editor 或 `model3.json` 的 `Parts` / `Textures` 检查 |
| C3 | **体积 ≤ 8 MB**（模型 + 首屏必需动作） | 看资源总大小；超过则只预加载 IDLE 与 PET_REACTION |

补充要求（非阻断，但影响体验）：
- 允许个人非商用展示（本项目定位）
- 有明确的署名要求且可满足（写进「关于」页）
- 有至少 3 个可用动作（IDLE / 抚摸回应 / 欢呼）

## 3. 候选清单（待逐个核验）

| 优先级 | 候选 | 来源 | 待验项 |
|---|---|---|---|
| 1 | **第三方「改変OK」模型** | Booth / nizima 等平台，作者标注可改変者 | C1 许可原文、C2 部件、C3 体积 |
| 2 | **CC0 / CC-BY 的 Live2D 模型** | 各类开源素材站 | 同上 + 署名方式 |
| 3 | 官方免费模型中的**未设禁止变更条款**者 | Live2D 官方样例（需逐个读下载页个别条款） | 个别条款 + 换装退化为"仅叠加不改变设计的配饰" |
| 4 | **放弃 Live2D**，改 Rive 或序列帧精灵图 | — | 无许可风险、体积更小、观感略弱 |

## 4. 验证步骤（在真实浏览器中执行）

```bash
# 1) 自托管 Cubism Core（避免 CSP 与 CDN 依赖）
#    必须放在 index.html 里，且先于应用脚本加载
#    <script src="/live2d/live2dcubismcore.min.js"></script>

# 2) 装渲染依赖
pnpm --filter @petfocus/web add pixi.js@^7 pixi-live2d-display

# 3) 启动开发服务器后打开首页，观察：
#    - 模型是否能加载（控制台无 CSP / WASM 报错）
#    - 帧率是否 ≥ 30 FPS（中端笔记本）
#    - 首屏是否被阻塞（模型必须懒加载）
#    - 点击身体是否有回应动作
#    - 页面切到后台时渲染是否停止（性能预算要求）
```

## 5. 为什么现在还没做（诚实说明）

本 spike **必须**在真实浏览器里跑，而我的运行环境：

- 没有浏览器可视化输出（只能验证 HTTP 响应与构建产物）
- 无法加载并渲染 Live2D 模型来观察效果
- 无法用真实鼠标验证「点击身体 → 抚摸回应」

因此我采取了**降低依赖风险**的做法：

1. 宠物渲染抽象成 `PetRenderer` 接口（`apps/web/src/features/pet/renderer.ts`）
2. 先实现 `CssPetRenderer`：零依赖、离线可用、无许可约束，
   **完整支持抚摸回应、状态映射、动作播放**
3. 业务逻辑（三维状态、喂食、换装、等级）全部与渲染器解耦并有单测覆盖
4. 待模型选定后，实现同接口的 `PixiLive2DRenderer` 即可替换，**不需要改任何业务代码**

这样即使 spike 结论是"没有可用模型"，宠物系统的功能完整性也不受影响。

## 6. 结论与决定

| 项 | 值 |
|---|---|
| 是否采用 Live2D | ⏳ 待验 |
| 选定模型 | ⏳ 待验 |
| 换装实现方式 | ⏳ 待验（优先模型内建部件；否则 Pixi 叠加层） |
| 署名文案 | ⏳ 待验（选定后写入「关于」页） |
| 兜底方案 | 已就绪：`CssPetRenderer`；若放弃 Live2D 则改用 Rive / 序列帧 |

**执行时机**：M5 收尾前，或在你有空时按第 4 节步骤跑一次并把结果回填到本文件。

## 7. 必须同时遵守的约束（无论选哪个模型）

- **换装能力必须在商品上如实标注**：`modelCompat: FULL | PARTIAL | NONE`
  （PRD AC-6.3.5）——做不到就标 `NONE` 并**不展示**该商品，不许假装能换
- **UI 不得声称是 Live2D**：若最终用 CSS/Rive 实现，界面与「关于」页都要如实说明
- 许可与署名信息必须出现在应用的「关于」页与 README
