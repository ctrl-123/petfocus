## 1. 问题定义：拖延到底是什么

### 1.1 结论先行

拖延**不是**「懒」，也不是「时间管理能力差」。学界主流解释是**情绪调节失败（Emotion Regulation Failure）**：

> 面对一件会引发焦虑/无聊/自我怀疑的任务时，大脑为了**立刻消除负面情绪**，选择去做一件当下情绪回报更高的事。拖延是「短期情绪止痛」，代价被推迟到未来支付（Sirois & Pychyl, 2013）。

这一点决定了产品的设计基调：

| 如果拖延是「懒」 | 如果拖延是「情绪调节失败」 |
|---|---|
| 解法 = 更狠的惩罚、更强的锁 | 解法 = **降低启动摩擦** + **把未来的代价挪到当下** + **给情绪一个替代出口** |
| 用户会恨这个软件 | 用户会和这个软件「站在一起对抗拖延」 |
| 结果：卸载 | 结果：留存 |

**本产品的定位由此确立：不是「监工」，是「外置的执行功能 + 情绪缓冲垫」。**

### 1.2 拖延的四个可干预机制

| 机制 | 通俗解释 | 本产品的作用点 |
|---|---|---|
| **时间折扣（Temporal Discounting）** | 未来的奖励/惩罚在心理上被打折，「现在刷 10 分钟视频」≫「三小时后交不了作业」 | 把「未来的后果」提前到现在：到点**强制**进入专注，代价即时发生 |
| **启动摩擦（Activation Energy）** | 开始做比继续做难 10 倍 | 用户**前一天晚上**就把待办写死（时间 + 事件），早上不需要决策，只需要执行 |
| **蔡格尼克效应 + 即时反馈缺失** | 刷视频有即时正反馈，写论文没有 | 每完成一个任务**立刻**发金币 + 奖励话术，把长周期回报切成碎片化即时回报 |
| **自我监控缺失（Metacognition Gap）** | 人严重低估自己浪费的时间（自评误差常达 2~3 倍） | 统计模块：专注日历 + 时长图表，把「我以为我学了 5 小时」变成「实际 1 小时 47 分」 |

### 1.3 为什么「惩罚」必须配合「陪伴」

纯惩罚型工具（锁机 App、家长控制）在自我施加场景下有一个致命缺陷：**用户就是执法者，也是被执法者**。当惩罚带来的痛苦超过拖延带来的痛苦时，用户会直接绕过或卸载——因为没人真的想惩罚自己。

因此本产品采用**三段式心理结构**：

```
        ┌─────────────────────────────────────────────┐
        │  1. 硬约束：专注/锁机模式拦截非白名单应用      │  ← 阻止「现在就想逃」的冲动（止损）
        │     退出有成本（次数配额 + 金币罚款）          │
        ├─────────────────────────────────────────────┤
        │  2. 软激励：金币 · 奖励话术 · 统计可视化       │  ← 让坚持有即时回报（拉动）
        ├─────────────────────────────────────────────┤
        │  3. 情感锚点：宠物                              │  ← 把「为自己自律」转成「为它自律」
        │     饿了会不开心 · 抚摸有回应 · 装扮是长期目标   │
        └─────────────────────────────────────────────┘
```

**宠物是整个产品的枢纽**：它把抽象的「自律」变成了具体的「照顾好一个小东西」。心理学上这是**承诺装置（Commitment Device）**与**拟人化投射**——用户对宠物的责任感，比对自己的责任感更稳定，因为对宠物负责不会触发「我在逼自己」的逆反。

### 1.4 关键设计推论（会直接影响 PRD）

| 编号 | 推论 | 对应功能决策 |
|---|---|---|
| R1 | 惩罚必须**可感知但不可摧毁** | 罚款扣金币而非清零；宠物会「蔫」但不会死/离家出走（否则用户直接弃游） |
| R2 | 决策要**前置**，执行时零决策 | 每日首次打开强制填今日待办 |
| R3 | 反馈必须**即时且具象** | 完成任务 → 金币飞入动画 + 奖励话术，延迟 < 300ms |
| R4 | 拦截必须**有优雅出口** | 每日/每月退出配额：给紧急情况留门，防止「一堵就砸墙」 |
| R5 | 数据要**可视化到有痛感** | 专注日历上大片空白比任何说教都有效 |
| R6 | 宠物要有**低成本高频互动** | 点击抚摸 + 随机动作，零成本、每次打开都能玩 |

## 2. 目标用户与用户旅程

### 2.1 用户画像

**主画像 · 张同学（20 岁，大二/大三学生）**
- 场景：宿舍或自习室，Windows 笔记本，手机在旁
- 痛点：有 DDL 但就是开不了工；打开书 5 分钟就摸手机；一天结束感到空虚
- 现有尝试：番茄钟 App（坚持 3 天）、Forest（种树但可以不管）、把手机放抽屉（失败）
- 关键诉求：**别让我自己决定，帮我决定**
- 付费意愿：低，但愿意为「好看 + 能装」花小钱

**副画像 · 李工（26 岁，工作 2 年，备考/副业）**
- 场景：下班后 20:00–23:00 的黄金三小时，常被短视频吃掉
- 痛点：计划做了无数版，从没执行超过一周；需要「打卡感」和「进度感」
- 关键诉求：**长期趋势可见 + 有陪伴感**
- 付费意愿：中，愿意为省心付费

**第三画像 · 王自由（30 岁，自由职业/远程办公）**
- 场景：家里办公，工作与生活无边界，随时可以「休息一下」然后休息三小时
- 痛点：没有外部约束（没有打卡、没有同事），自律完全靠自己
- 关键诉求：**模拟外部约束 + 时间账本**
- 付费意愿：高

### 2.2 关键用户旅程（当前 vs 期望）

**旅程 A：早上打开电脑**

```
当前：开机 → 微信/微博/游戏图标在桌面 → 点开 → 两小时后才想起今天要干什么
                                ↑ 决策点在最脆弱的时刻
期望：开机 → 首页直接弹出「今天要做什么？」→ 填写 2~3 件事 + 时间 → 收起 → 看到宠物
                                ↑ 决策前移到精力尚可的早晨，且只有一次
```

**旅程 B：待办时间到了，正在刷视频**

```
当前：心里知道该干活了 → 「再看 5 分钟」→ 无限循环
期望：屏幕被专注模式接管 → 非白名单应用全部打不开 → 想退出要消耗今日唯一一次机会
                                ↑ 冲动被物理阻断，但门没焊死
```

**旅程 C：一天结束**

```
当前：感觉很忙但说不出干了什么 → 空虚 + 自责 → 第二天更不想开始
期望：看到今日专注 2h15m、完成 3/4 件事、金币 320、宠物穿着新帽子
                                ↑ 有据可依的满足感，形成正循环
```

**旅程 D：非待办时间，突然想刷手机**

```
当前：没有约束，随手就刷
期望：主动开启「锁机 60 分钟」→ 结束后按 12 金币/小时结算 → 宠物吃上饭
                                ↑ 把「自律」变成一个有收益的动作
```

### 2.3 使用频率预期

| 功能 | 预期触发频率 | 设计含义 |
|---|---|---|
| 每日待办填写 | 1 次/天 | 必须是轻量表单，30 秒内完成 |
| 专注模式 | 2~6 次/天 | 启动/结束动画必须短，不能耽误正事 |
| 锁机模式 | 0~3 次/天 | 入口必须在首页一级 |
| 宠物互动 | 5~20 次/天 | 必须极低延迟、离线可用 |
| 商城 | 1~3 次/周 | 商品更新节奏要有新鲜感 |
| 统计查看 | 1 次/天 | 打开即出图，不做二次筛选 |
| 专项模块（健身/饮食/记账） | 1~5 次/天 | 三个模块共用「侧边栏 + 卡片」范式，降低学习成本 |

## 3. 竞品研究

### 3.1 横评表

| 产品 | 类型 | 核心机制 | 强制力 | 优点 | 缺点（我们的机会） |
|---|---|---|---|---|---|
| **Forest 专注森林** | 移动/桌面 | 专注种树，中途离开树会枯；金币买真树/装扮 | 中（可放弃，枯树惩罚轻） | 即时反馈极佳、情感化设计教科书 | 无待办计划、无时间表、无统计深度；「树枯了」不会真的痛 |
| **番茄 ToDo** | 移动 | 番茄钟 + 待办 + 白名单 + 强制模式 | 中高（需手动开启严格模式） | 功能全、数据细 | 界面工具感重、无情感陪伴；严格模式依赖用户自觉开启 |
| **种豆得豆 / 专注海洋** | 移动 | 同 Forest 变体 | 中 | 视觉讨喜 | 同质化严重，无差异化护城河 |
| **Cold Turkey Blocker** | Windows 桌面 | 拦截网站/应用，可设锁定计划，**Pro 版防卸载** | **高** | 拦截力真实有效 | 界面像 2005 年、零情感设计、无激励、纯「监狱」；用户对抗情绪强 |
| **Freedom** | 跨平台 | 跨设备拦截 | 高 | 跨设备同步好 | 订阅制作、无陪伴、无成长体系 |
| **Focusme / SelfControl** | 桌面 | 定时拉黑 | 高（SelfControl 无法提前解除） | 极硬核 | 无退出配额 → 遇紧急事项只能强制重启，体验崩溃 |
| **Windows 专注助手 / 时钟** | 系统 | 免打扰 + 番茄钟 | 低（仅隐藏通知） | 系统级、零安装 | 不拦应用，只是「静音」，形同虚设 |
| **iOS 屏幕使用时间** | 系统 | 应用限额 + 家人共享密码 | 高 | 系统级、最难绕过 | 被监护人易破解（改时间/卸载）；无激励、无宠物、无待办 |
| **Habitica** | Web/移动 | RPG 化任务，宠物 + 装备 + 公会，未完成扣血 | 低（纯自觉，不拦应用） | 游戏化激励体系最成熟、金币经济完整 | **完全不拦应用**，全靠自觉；重度社交依赖；像素风对部分人无吸引力 |
| **Finch 自养小鸟** | 移动 | 宠物随完成度成长，点击互动 | 低 | 宠物情感设计一流、留存高 | 不拦应用、无待办时间表、无锁机 |
| **Notion / 飞书待办** | 生产力 | 任务管理 | 无 | 灵活强大 | 无任何约束与激励，拖延者用不上 |
| **「每天吃什么」转盘类小程序** | 工具 | 随机选餐 | 无 | 解决选择恐惧，单点极爽 | 用完即走，无留存 |

### 3.2 竞品空白区（我们的差异化定位）

把市场按两个轴切开：**强制力**（软 → 硬）× **情感陪伴**（无 → 强）。

```
强制力 高
   │
   │  Cold Turkey        ★ 空白区（本产品）
   │  Freedom              · 硬约束 + 有温度
   │  SelfControl          · 拦截 + 宠物 + 金币经济 + 统计深度
   │
   │  番茄ToDo / Forest         Habitica / Finch
   │                     
   └──────────────────────────────────────────── 情感陪伴 强
   低
```

**结论：没有任何一款主流产品同时做到了「真实拦截应用」和「强情感陪伴」。**
- 硬核拦截工具（Cold Turkey / Freedom）用户抱怨「像坐牢」，且毫无坚持动力；
- 情感陪伴产品（Finch / Habitica）完全不拦应用，拖延者依然会去刷视频。

**PetFocus 的定位一句话：给「监狱」装上「宠物」。**
用户不是为了被管而打开它，是为了**回家看宠物**而打开它——但一旦打开，规则就生效了。

### 3.3 可借鉴的具体机制（逐条评估）

| 借鉴对象 | 机制 | 是否采纳 | 理由 |
|---|---|---|---|
| Forest | 中途离开 → 视觉惩罚 | ✅ 采纳（转化为：违规 > 30s 则本次专注收益减半 + 宠物不开心） | 视觉化损失比文字警告有效 |
| Forest | 金币买装扮 | ✅ 采纳 + 强化（商城独立页面，商品分食物/装扮/家具） | 长期目标锚点 |
| 番茄 ToDo | 白名单 | ✅ 采纳（进程级 + 网站级） | 核心需求 |
| Cold Turkey | 锁定计划（预定时间自动生效） | ✅ 采纳并升级为「到待办时间自动进入」 | 用户明确需求，且比手动锁定更贴合 |
| SelfControl | 无法提前解除 | ❌ 不采纳 | 遇紧急事项会崩溃；改为「配额式有限解除」 |
| Habitica | 未完成扣血 | ⚠️ 部分采纳 | 扣血量必须温和（扣金币，不清零、不死亡） |
| Habitica | 公会/社交 | ❌ 本期不做 | 个人项目，社交带来审核/合规成本，收益低 |
| Finch | 点击抚摸有反馈 | ✅ 采纳（核心交互） | 零成本高频情感连接 |
| iOS 屏幕使用时间 | 家人共享密码 | ⏭️ 后续版本（V2 考虑「监督人」模式） | 需要账号体系与服务端，MVP 不做 |
| 转盘类小程序 | 随机选餐 | ✅ 采纳（饮食模块子功能） | 用户明确要求，且是低成本高感知的亮点 |

## 4. 需求假设与验证计划

> 以下每条都是**假设**，不是事实。写出来是为了在后续迭代中检验，避免我们把猜测当需求。

| 编号 | 假设 | 验证方式 | 若假设不成立时的应对 |
|---|---|---|---|
| H1 | 用户愿意每天晚上/早上花 30 秒填待办 | 上线后看「每日待办填写完成率」 | 降级为「快速添加 1 件事」+ 智能推荐模板 |
| H2 | 「到点强制进入专注」不会引发强烈反感 | 看「配额消耗率」和「次日留存」 | 增加 3 分钟宽限期与「本次跳过但记录」选项 |
| H3 | 宠物互动能提升留存 | A/B：有宠物 vs 无宠物（或宠物隐藏） | 若无效，重心迁回统计与激励话术 |
| H4 | 金币经济不会通胀 | 监控「持有金币中位数」「商城购买率」 | 动态调整定价与产出公式 |
| H5 | 用户会真的用健身/饮食/记账三个模块 | 看各模块 DAU 占比 | 砍掉最弱的一个，把位置让给自定义模块 |
| H6 | 「违规检测 + 惩罚」在 Web 上仍有威慑力 | 看「专注中切走次数」与「自我报告自律感」 | 把桌面增强包从「可选」提为「推荐安装」 |
| H7 | 用户能接受 AI 分析饮食（数据上云） | 看 AI 分析的调用率与关闭率 | 纯本地库模式，AI 完全可选 |

**MVP 阶段不做的验证**：真金白银的商业化验证（本项目为个人作品，无营收目标）。

## 5. 可行性边界清单 ⚠️

> 这是本文档最重要的一节。**它决定了 PRD 中哪些需求必须改写、哪些必须标注降级方案。**
> 结论来源：浏览器安全模型 + 现代操作系统权限模型 + 实测环境勘察。

### 5.1 环境勘察实测记录

| 项 | 实测结果 | 影响 |
|---|---|---|
| 操作系统 | Windows（`Win32_OperatingSystem` 查询被安全策略拒绝，无法读取版本号；`$env:USERNAME = 张鑫`） | 目标平台确认为 Windows 优先 |
| 当前会话管理员权限 | **否**（`IsInRole(Administrator) = False`） | 原生拦截方案需要提权，开发时需要以管理员身份运行一次 |
| Node.js | ✅ 已安装 `D:\APP\Node.js\intall\node.exe` | 前端工具链可用 |
| pnpm | ❌ 未安装 | 需先 `npm i -g pnpm`（文档已记录替代方案） |
| git | ❌ 未安装 | **必须补装**，否则无法版本管理与部署到 Vercel |
| .NET SDK | ✅ 已安装 `C:\Program Files\dotnet\dotnet.exe` | 桌面增强包（C#）技术路线可行，无需额外装环境 |
| Rust / cargo | ❌ 未安装 | 排除 Tauri 方案，避免引入额外工具链 |

### 5.2 边界清单（逐条裁决）

### 5.4 必须写进 PRD 的「如实说明」文案

对外（README / 关于页面）必须明确写清，避免面试官或用户误判：

> 浏览器没有权限结束其他进程，因此**纯网页版无法真正阻止你打开微信或游戏**。
> 网页版提供的是「强制全屏 + 切走记录 + 收益惩罚 + 到点唤回」的软约束；
> 项目同时提供一个可选的 Windows 原生增强包，安装后即可实现真实的应用拦截。
> 这是有意的架构选择：把跨不过去的平台边界，用一个最小化的原生伴侣进程补上。

## 7. 成功指标

> 本项目为**个人作品 + 简历项目**，没有商业营收目标。因此指标分两类：**产品健康度**（证明设计有效）与**作品说服力**（证明工程能力）。

### 7.1 北极星指标

**NSM：每周「有效专注次数」= 专注时长 ≥ 15 分钟且违规时长 < 20% 的专注会话数**

理由：单纯看「总专注时长」会奖励挂机；加入违规占比才能反映真实自律。

### 7.2 产品健康度指标（护栏）

| 指标 | 定义 | 目标（上线 4 周内） |
|---|---|---|
| 每日待办填写完成率 | 完成填写的天数 / 打开天数 | ≥ 70% |
| 专注会话完成率 | 未被中途放弃的专注 / 启动的专注 | ≥ 60% |
| 配额消耗率 | 消耗退出次数 / 可用次数 | ≤ 40%（过高说明太苛，过低说明在绕开） |
| 次日留存 | 次日再次打开 | ≥ 45% |
| 宠物互动率 | 有互动的会话 / 总会话 | ≥ 50% |
| 金币收支健康 | 人均持有金币中位数 | 稳定在「攒 3~5 天可买一件装扮」区间 |
| 统计页访问率 | 访问统计 / 总会话 | ≥ 30% |
| 专项模块留存 | 至少一个专项模块周使用 ≥ 3 天 | ≥ 25% 用户 |

### 7.3 作品说服力指标

| 指标 | 目标 |
|---|---|
| 可访问演示链接 | 在线可访问，手机可打开 |
| 演示模式加载时间 | 点击到完整视图 < 1.5s |
| Lighthouse 性能/可访问性 | ≥ 90 / ≥ 90 |
| 首屏 JS 体积（gzip） | < 350 KB（Live2D 资源异步加载，不计入首屏） |

## 8. 开放问题的最终裁决（已全部确认）

**状态：✅ 全部确认（2026-02-14）**。需求方已逐条拍板，以下为锁定结论。
编号与 `docs/02-PRD-产品需求文档.md` 第 16.2 节一致，两处必须同步修改。

| # | 问题 | **最终结论（已锁定）** | 影响 |
|---|---|---|---|
| Q1 | **配额语义与重置时区**：专注「每日 1 次、每月 5 次」是「每天最多 1 次且整月不超 5 次」，还是「每日独立 1 次、月上限 5 次」？ | 专注：每日 1 次 + 每月累计上限 5 次；锁机：仅每月 5 次；两套独立。重置按**本地自然日 04:00**（照顾熬夜用户），**服务端时间为权威** | 核心规则，决定数据模型与结算方式 |
| Q2 | 自动进入专注时用户正在开会/上课怎么办 | **3 分钟宽限期 + 「本次跳过」**（不消耗月配额，扣 10 金币，每日上限 2 次，需填原因并计入统计） | 影响体验与反感度 |
| Q3 | 「每日首次打开」的判定：开机自启时早上 6 点就弹表单是否合适 | 判定为「当天未填写待办 **且当前 ≥ 07:00**」时弹出；早于 07:00 的首次打开顺延到 07:00 后的首次打开 | 影响每日填写完成率（H1） |
| Q4 | 金币定价与产出公式 | 基础 **20 币** × 时长系数（0.6/1.0/1.5/2.0/2.3）× 质量系数（0.2–1.2）+ 准时加成 10；每日产出硬上限 **400 币**；锁机 12 币/小时；食物 30–260 币；装扮 150–2000 币 | 决定经济系统是否通胀（RK3） |
| Q5 | 违规惩罚细节 | 切走累计 **> 30 秒**才计为违规并暂停计时；违规占比 > 20% 收益 ×0.5；越界退出：本次收益清零 + 扣 50 币（扣至 0，不产生负债）+ 宠物「蔫」30 分钟 | 影响留存与情绪 |
| Q6 | 白名单粒度 | 进程级（exe）+ 网站级（域名）双层；另设「系统必需进程」内置豁免清单防止误杀；**会话进行中不可编辑** | 影响桌面增强包复杂度与安全性 |
| Q7 | 三个专项模块是否都要做进 MVP | 饮食 + 记账进 **P0**；健身**核心**（打卡/项目记录/连续天数）进 P0，深度分析（趋势、里程碑细化）入 v0.2 | 影响周期（RK8） |
| Q8 | 是否要账号体系 + 数据驻留边界 | **不做任何账号体系**（无注册/登录/邮箱/密码/用户资料）。身份仅为一个**前端生成的匿名设备 ID**（UUID 存 localStorage，用户不可见）；**所有业务数据只存本机**，不上云；换设备靠导出/导入 JSON。后端用 **Supabase Edge Function 免费版**，仅负责结算与 AI 代理；前端托管 **Vercel 免费版** | 影响部署架构与复杂度（原建议是「可选登录 + 云备份」，**已被否决**） |
