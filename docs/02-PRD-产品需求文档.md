## 1. 产品概述

### 1.1 一句话定位

> **一个会管住你、也会陪着你的个人工作台：它在你该干活的时候把电脑锁住，在你干完之后给你的宠物发工资。**

- 中文名：**自律岛**
- 英文代号：**PetFocus**
- 形态：**PWA Web 应用**（线上可直接访问）+ **可选 Windows 原生增强包**（提供真实应用拦截）
- 目标用户：18–32 岁、有明确想做但总开不了工的学生与职场人

### 1.2 差异化（来自需求研究第 3 节）

| 竞品类别 | 它们有什么 | 它们缺什么 | PetFocus 补上 |
|---|---|---|---|
| 硬核拦截工具（Cold Turkey / Freedom） | 真实拦截 | 冰冷、无激励、零陪伴 | 宠物 + 金币 + 成长体系 |
| 情感陪伴产品（Finch / Habitica） | 宠物、金币、成长 | 完全不拦应用，拖延者照样刷视频 | 真实拦截（网页软约束 + 原生硬拦截） |
| 番茄钟（Forest / 番茄 ToDo） | 计时、白名单、种树 | 无待办时间表驱动、无深层统计 | 到点自动进入 + 专注日历 + 三模块工作台 |

### 1.3 产品目标与反目标

**目标（本期要做）**
1. 让用户「早上写下今天要做什么，到点不用再决策」。
2. 让用户在冲动刷视频的瞬间遇到真实阻力，但保留优雅出口。
3. 让每一次专注都有即时、具象、可累积的回报（金币 + 话术 + 宠物）。
4. 让用户能看见自己真实的时间去向。

**反目标（本期明确不做，防止范围失控）**
- ❌ 不做社交、公会、排行榜（审核与合规成本高，收益低）
- ❌ 不做多人协作待办
- ❌ 不做移动端原生 App（PWA 之外不投入）
- ❌ 不做账号体系（无注册、无登录、无邮箱、无密码、无用户资料）。身份仅为一个**前端生成的匿名设备 ID**（UUID，存 localStorage，用户不可见、无需感知）
- ❌ 不做云备份与跨设备同步（数据只在本机；换设备靠导出/导入 JSON）
- ❌ 不做内容社区 / 日记 / 树洞
- ❌ 不做商业化付费墙

## 2. 角色与权限

MVP 为**单用户单设备**模型，但数据模型预留多用户字段。

| 角色 | 说明 | 权限 |
|---|---|---|
| 用户（本人） | 唯一核心角色 | 全部功能 |
| 监督人（V2） | 可为他人设置配额与白名单，持有解除密码 | V2 不做 |
| 桌面增强包 | 本机伴侣进程 | 接收白名单、上报违规；**无任何数据读取权**（只回传进程名与时间戳） |
| 演示访客 | 打开演示模式的人 | 只读演示数据，写入隔离在独立命名空间，退出即清空 |

## 4. 全局规则

### 4.1 时间与「日」的定义

| 规则 | 定义 |
|---|---|
| 自然日边界 | **本地时间 04:00**（凌晨 4 点前算前一天，照顾熬夜用户） |
| 配额重置 | 每日配额在自然日边界重置；每月配额在每月 1 日 04:00 重置 |
| 时区 | 以设备本地时区为准；服务端校验使用 UTC 时间戳 + 客户端时区偏移 |
| 防回绕 | 所有配额消耗与金币结算以**服务端时间**为权威；本地时间仅用于展示与乐观更新 |

### 4.2 会话状态机（全局唯一）

系统同一时刻只能处于一种「强约束状态」：

```
        ┌────────┐   到待办时间/手动开始    ┌──────────┐
        │ IDLE   │ ───────────────────────▶ │ FOCUSING │
        │ 空闲   │ ◀─────────────────────── │ 专注中   │
        └───┬────┘      正常结束/提前退出    └────┬─────┘
            │                                     │
            │ 手动开启锁机                    （专注未结束不可开锁机）
            ▼                                     │
        ┌────────┐   到时/提前退出                 │
        │ LOCKED │ ◀──────────────────────────────┘
        │ 锁机中 │
        └────────┘
```

**规则**
- G1：`FOCUSING` 或 `LOCKED` 期间，**不允许**启动另一个约束会话（按钮置灰并说明原因）。
- G2：页面刷新、浏览器关闭后重新打开，必须按时间戳**恢复**到正确的状态与剩余时长，不得重置。
- G3：设备休眠/唤醒后，按真实时间戳补偿计算；若已超时，直接进入结算流程。
- G4：任何时候必须提供「紧急停止」路径，但其代价受配额与惩罚规则约束（见第 7 章）。

### 4.3 通知策略

| 时机 | 通知内容 | [Web] | [原生] |
|---|---|---|---|
| 待办前 5 分钟 | 「5 分钟后进入专注：写实验报告」 | 页内弹窗 + Web Notification（需授权） | 系统通知 + 托盘气泡 |
| 待办时刻 | 「专注开始」 | 页内**全屏**接管 | 强制前置窗口 + 开始拦截非白名单进程 |
| 待办前 5 分钟（页面已关闭） | 同上 | Web Push（需已安装 PWA、HTTPS、用户授权）；失败则静默记录，下次打开补提示 | 原生进程直接弹通知（可靠） |
| 锁机结束前 1 分钟 | 「还有 1 分钟，准备收尾」 | 页内提示 | 系统通知 |
| 宠物饥饿 | 「宠物饿了」 | 页内气泡（不打扰） | 可选系统通知 |

**通知克制原则**：单日系统级通知 ≤ 8 条；所有通知可在设置中按类型关闭。

## 5. 功能需求 · FR-1 专注模式

### FR-1.1 用户故事

> 作为一名总是「再看五分钟」的学生，我希望到了我计划的时间点，电脑自动进入专注状态并挡住让我分心的应用，这样我就不需要靠意志力做决定了。

### FR-1.2 触发方式

| 触发源 | 规则 | 优先级 |
|---|---|---|
| 待办到点自动触发 | 待办项的「开始时间」到达时自动进入；提前 5 分钟通知 | P0 |
| 手动开始 | 用户点击「开始专注」，可为某个待办或自由专注（需填事件名） | P0 |
| 连续待办衔接 | 上一个待办结束后，若 3 分钟内是下一个待办，提供「直接进入下一个」 | P1 |

### FR-1.3 界面要求

**构成元素**
1. **计时环**：剩余时间环形进度，中心显示 `MM:SS`；环形颜色随时间衰减变化（绿 → 黄 → 红）。
2. **任务信息**：当前待办事件名、计划时长、已完成时长。
3. **约束状态指示**：
   - `[Web]` 显示「软约束模式 · 未安装桌面增强包」并提供安装引导链接；
   - `[原生]` 显示「硬约束已生效 · 已拦截 N 个应用」。
4. **白名单入口**：会话中可查看白名单，**不允许修改**（防止临阵放水）；修改需结束会话。
5. **配额面板**：显示「今日退出机会 1/1 · 本月剩余 4/5」，实时更新。
6. **违规计数**：本次会话已切走 X 次 / 累计 Y 秒。
7. **结束按钮**：文字为「结束本次专注」；点击后弹出**二次确认**并明确显示代价。
8. **紧急停止**：位于二级菜单，标注「会消耗配额」。
9. **粒子/氛围**：进入时 0.6s 遮罩过渡，结束后 1.2s 结算动画。

### FR-1.4 约束能力验收标准 ⚠️

| 编号 | 需求 | [Web] 验收标准（纯网页） | [原生] 验收标准（增强包） |
|---|---|---|---|
| AC-1.4.1 | 非白名单应用不能使用 | 无法阻止。**必须**做到：① 全屏接管页面；② 监听 `visibilitychange` / `blur` / 窗口失焦，切走即记录开始时间，回来后累计违规秒数；③ 违规 > 30 秒暂停计时；④ 会话结算时按违规占比扣减收益；⑤ 会话中每 60 秒尝试重新获取全屏并提示「不要离开」。**不得**在 UI 上声称已拦截应用 | ① 通过本地 WS 向增强包下发白名单；② 增强包对非白名单前台进程执行「结束」或「挂起」；③ 违规事件实时回传并在会话页显示拦截日志；④ 增强包未运行时网页自动降级为 `[Web]` 行为，**不得报错或卡死** |
| AC-1.4.2 | 白名单管理 | 支持增删改查：应用名（exe 名/显示名）、网站域名、系统豁免（内置不可删：`explorer.exe`、`dwm.exe`、输入法、无障碍工具、音频服务等）。会话进行中不可编辑 | 同左，且变更后 2 秒内下发给增强包生效 |
| AC-1.4.3 | 到点自动进入 | 页面存活时：到点 ±1 秒内进入专注页。页面已关闭时：无法自动进入；**必须**在下次打开时给出「你错过了 X 点的专注」提示并提供「补做 25 分钟」。已授权通知且已安装 PWA 时尝试 Web Push 提醒 | 到点由原生进程强制唤起并立即开始拦截，误差 ≤ 2 秒 |
| AC-1.4.4 | 强制全屏 | 进入时调用 Fullscreen API；用户按 ESC 退出全屏时，记录一次「越狱尝试」并显示「已记录，可用增强包彻底阻止」提示，同时尝试重新全屏（最多 3 次，间隔 5 秒，之后不再骚扰以免激怒用户） | 全屏 + 拦截 Alt+Tab / Win 键（可配置开关，默认关闭，因为强拦热键体验争议大） |
| AC-1.4.5 | 退出配额 | 专注模式：**每日 1 次 + 每月累计上限 5 次**。消耗顺序：优先扣每日额度，每日额度用尽后从月度池扣。额度用尽后的退出**仍然允许**，但触发惩罚（见 AC-1.4.7） | 同左 |
| AC-1.4.6 | 特殊事件应对 | 提供「**本次跳过**」：不消耗月配额，需填写原因（下拉：会议/上课/身体不适/紧急事务/其他），每日最多 2 次，每次扣 10 金币，并计入统计的「跳过率」 | 同左 |
| AC-1.4.7 | 越界惩罚 | 配额用尽后强行退出：① 本次会话收益清零；② 扣 50 金币（不足则扣至 0，不产生负债）；③ 宠物进入「蔫」状态 30 分钟（动作迟缓、表情低落，可通过抚摸或喂食 30 金币的食物提前恢复）；④ 记录到「越界日志」 | 同左 |
| AC-1.4.8 | 到点缓冲 | 到点后给 **3 分钟**宽限期，页面顶部显示横幅与倒计时，可点击「立即开始」。宽限期结束仍未开始，自动进入专注 | 同左 |

### FR-1.5 结算与奖励

会话结束时展示结算页，包含：

| 元素 | 说明 |
|---|---|
| 专注时长 | 实际有效时长（扣除违规暂停时间） |
| 完成度 | 有效时长 / 计划时长，以百分比 + 环形展示 |
| 金币产出 | 明细拆解（基础 + 时长加成 + 准时加成 − 违规扣减 − 惩罚） |
| 违规统计 | 切走次数、累计违规秒数、占比 |
| **奖励话术** | 按表现分档随机抽取，见下表 |
| 宠物反应 | 宠物播放「开心/欢呼/平静/蔫」动作（依表现而定） |
| 后续操作 | 「查看统计」「再来一个」「去商城」 |

**奖励话术分档（每档 ≥ 8 条，避免重复感；文案风格：朋友式鼓励，不说教、不道德绑架）**

| 档位 | 条件 | 话术示例 |
|---|---|---|
| S 档 | 完成度 ≥ 100% 且违规 0 次 | 「全程零走神，这专注力拿去考试都够用了。」/「你刚刚的样子，值得被截图。」 |
| A 档 | 完成度 ≥ 80% 且违规占比 < 10% | 「稳稳当当，宠物在你脚边转了三圈。」 |
| B 档 | 完成度 ≥ 50% | 「今天先到这，明天的你会感谢现在的你。」 |
| C 档 | 完成度 < 50% 且非主动放弃 | 「完成了一半也是完成，至少你坐下来过。」 |
| D 档 | 中途放弃 / 违规严重 | 「没关系，先喝口水。要不要把任务切小一点？」（**禁止**出现指责性文案） |

> **文案红线**：不得使用「你真懒」「又失败了」「对不起宠物」等羞辱性表达。惩罚只体现在数字与宠物状态上，不体现在语言攻击上。

## 6. 功能需求 · FR-2 待办集

### FR-2.1 用户故事

> 作为一名早上打开电脑就不知道从哪开始的人，我希望一打开就被温和地问「今天要做什么」，填完就再也不用纠结，到点它会自己来找我。

### FR-2.2 每日首次填写流程

| 编号 | 需求 | 验收标准 |
|---|---|---|
| AC-2.2.1 | 首次打开自动弹出 | 判定条件：`当天（04:00 边界）尚未填写今日待办` **且** `当前时间 ≥ 07:00`。[Web/原生] 满足条件时，首页之上弹出**模态填写表单**，无法通过点击遮罩关闭，必须「保存」或「今天先跳过」。 |
| AC-2.2.2 | 凌晨打开不弹 | 若首次打开时间 < 07:00，则**不弹**；当天 ≥ 07:00 后的首次打开再弹。若当天再未打开，则不弹。 |
| AC-2.2.3 | 非首次打开不弹 | 当天已填写过（哪怕只填了 1 条），后续打开直接进首页展示待办，**不再弹窗**。 |
| AC-2.2.4 | 跳过也要留痕 | 点击「今天先跳过」后当天不再弹，但在首页顶部保留一条可点击的提示条「今天还没排计划 · 花 30 秒排一下」，并在统计中记录为「跳过填写」。 |
| AC-2.2.5 | 填写表单字段 | 必填：**开始时间** + **事件名**。选填：预计时长（默认 25 分钟）、优先级（高/中/低）、备注、是否重复（每日/工作日/自定义）。 |
| AC-2.2.6 | 快速填写 | 支持自然语言速记：输入「9点 写实验报告 1小时」自动解析为时间 + 事件 + 时长；解析结果可编辑。 |
| AC-2.2.7 | 批量与模板 | 支持从「昨天的待办」「模板库」一键导入；支持一次添加多条（回车即新增一行）。 |
| AC-2.2.8 | 时间冲突提示 | 两条待办时间重叠时给出黄色提示，但不阻止保存。 |

## 13. 界面与视觉方向

### 13.1 设计基调

- **关键词**：温暖、安静、有生命力、不吵闹
- **反对**：纯黑科技感、KPI 仪表盘式压迫感、荧光色游戏 UI
- **主张**：做一个「你会想打开看看宠物」的地方，而不是「监控你」的地方

### 13.2 页面与状态覆盖清单（每个页面需设计以下状态）

| 页面 | 必须覆盖的状态 |
|---|---|
| 首页 | 空待办 / 有待办 / 专注中 / 锁机中 / 离线 / 演示模式 / 宠物蔫 |
| 专注会话 | 进行中 / 违规中 / 暂停 / 宽限期 / 结算 / 配额用尽确认 |
| 待办填写 | 空表单 / 校验错误 / 自然语言解析预览 / 跳过确认 |
| 锁机 | 时长选择 / 预设选择 / 进行中 / 提前退出确认 / 结算 |
| 统计 | 无数据（引导）/ 有数据 / 加载 / 演示数据 |
| 商城 | 余额充足 / 余额不足 / 已拥有 / 上新 / 购买确认 |
| 全局 | 断网 / 结算中 / 结算失败（本地已记录，待重试）/ 设备 ID 缺失或异常 / 权限被拒（通知/全屏） |

### 13.3 关键设计原则

1. **倒计时是第一信息**：任何约束状态下，剩余时间是页面上最大的元素。
2. **代价必须可见**：点「退出」之前，必须看到「将消耗今日唯一一次机会」。
3. **惩罚不羞辱**：错误文案永远指向「方法」而非「人格」。
4. **宠物不遮挡操作**：它是氛围，不是障碍。
5. **移动端优先做减法**：小屏只保留待办、状态、宠物、统计；拦截配置收纳进设置。

## 14. 主要流程与异常分支

### 14.1 主流程：到点自动进入专注

```
待办开始前 5 分钟
  → 通知 + 页内横幅「5 分钟后进入专注」
待办时刻
  → 进入 3 分钟宽限期（可点「立即开始」）
宽限期结束
  → 全屏接管 → 若原生增强包在线，下发白名单并开始拦截
  → 计时开始；每 60 秒检查一次可见性/全屏状态
  → 违规检测：切走 > 30s → 暂停计时并累计
计划时长结束
  → 结算页（时长/金币/违规/话术/宠物反应）
  → 写入记录 → 入同步队列 → 更新宠物状态与金币
```

### 14.2 异常分支清单（必须全部有明确处理）

| # | 异常 | 处理 |
|---|---|---|
| E1 | 待办时间到达时用户不在电脑前 | 宽限期结束后进入专注；用户回来后看到「已进行 12 分钟」，可选择继续或重新开始 |
| E2 | 会话中浏览器被强关 | 状态持久化；重新打开时提示「你有一个未完成的专注（已进行 18 分钟）」，提供「继续 / 结束并结算 / 放弃」 |
| E3 | 会话中设备休眠 | 唤醒后按真实时间补偿；若已超时则直接结算 |
| E4 | 系统时间被用户手动修改 | 同时记录 `performance.now()` 单调时钟与 `Date.now()`；两者偏差 > 60 秒时以服务端时间为准，并提示「检测到时间异常，已按服务器时间结算」 |
| E5 | 断网 | 全部操作本地完成并入队；顶部显示「离线中，X 条待同步」；联网后自动重试（指数退避） |
| E6 | 同步冲突（同一待办在两处被改） | 以服务端时间更晚的一次为准；被覆盖的一方写入「冲突历史」可供查看 |
| E7 | 原生增强包未安装 / 崩溃 | 降级为 `[Web]` 软约束，顶部明确提示「硬约束未生效」，不报错、不阻塞 |
| E8 | 通知权限被拒 | 页内提示 + 引导如何在浏览器设置中开启；功能降级为页内横幅提醒 |
| E9 | 全屏被拒（浏览器策略要求用户手势） | 显示「点击进入专注」大按钮，用户点击后立即全屏 |
| E10 | Live2D 模型加载失败 | 展示静态立绘占位 + 「宠物正在休息」文案；功能不中断 |
| E11 | AI 分析超时 / 配额用尽 | 标记为「待估算」，提供手动输入营养值的入口；本地库仍可用 |
| E12 | 存储配额满（IndexedDB 被浏览器限制） | 提示导出数据 + 自动清理 90 天前的动画缓存；保留核心记录 |
| E13 | 配额用尽后用户点退出 | 三次确认（第二次需输入「确认」二字），明确列出全部代价，之后仍允许退出 |
| E14 | 用户在专注中尝试卸载/清数据 | `[Web]` 无法阻止，记录并提示；`[原生]` 可提供「锁定期间禁止退出」选项（默认关闭） |
| E15 | 跨天会话（23:50 开始 30 分钟专注） | 归属到开始时刻所在自然日；金币与统计按此口径 |
| E16 | 两条待办时间重叠 | 允许保存，但进入专注时弹出选择「做哪一个」；选中的优先，另一个标记为顺延 |
| E17 | 金币余额为 0 时被罚款 | 扣至 0 为止，**不产生负债**；可选的「欠款」机制不做（会造成厌恶感） |
| E18 | 用户连续多天完全不使用 | 不发任何骚扰通知；首页仅显示一句温和文案 |

### 16.2 需求研究开放问题的最终裁决

**状态：全部已确认（2026-02-14）**。以下为锁定结论，编码阶段以此为准，不得再自行变更。
编号与 `docs/research/01-需求研究报告.md` 第 8 节一致。

| # | 问题 | **最终结论（已锁定）** |
|---|---|---|
| Q1 | 配额语义与重置时区 | 专注「每日 1 次 + 每月累计上限 5 次」；锁机「仅每月 5 次」；两套独立。均按本地 **04:00** 自然日边界，**服务端时间为权威** |
| Q2 | 会议/上课打断 | **3 分钟宽限期 + 「本次跳过」**（不耗月配额，扣 10 金币，每日上限 2 次） |
| Q3 | 每日首次打开判定 | 当天未填写待办 **且当前 ≥ 07:00** 时弹出模态表单；否则顺延至当天 07:00 后的首次打开 |

| Q5 | 违规惩罚 | 违规 > 30 秒暂停计时；违规占比 > 20% 收益 ×0.5；越界退出：收益清零 + 扣 50 币 + 宠物蔫 30 分钟（见 AC-1.4.7） |
| Q6 | 白名单粒度 | 进程级（exe）+ 网站级（域名）双层 + 内置「系统必需进程」豁免；**会话进行中不可编辑** |
| Q7 | 三个专项模块的 MVP 深度 | 饮食 + 记账进 P0；健身**核心**（打卡/项目/连续天数）进 P0，深度分析（趋势/里程碑细化）入 v0.2 |
| Q8 | 账号体系与数据驻留 | **不做任何账号体系**（无注册/登录/邮箱/密码）。身份仅为一个**前端生成的匿名设备 ID**（UUID 存 localStorage，用户不可见）；**所有业务数据只存本机**，不上云；换设备靠导出/导入 JSON |
| Q9 | Live2D 模型选型 | **先用免费授权模型**。要求许可允许个人非商用展示 + **允许修改**（换装需要）+ 体积 ≤ 8 MB；必须完成强制署名。**注意**：官方免费模型中的 Hiyori Momose / Miara 明令「不得对设计做任何变更」，不可用于换装，详见 15.2 节。若找不到合适模型，退 Rive / 序列帧 |
| Q10 | 桌面增强包（真实拦截） | **做**，排期在 Web 版跑通之后（v0.2），Windows only，需管理员权限 |

## 17. 金币经济系统（完整数值定义）

> 所有数值集中在 `packages/shared/src/config/economy.ts`，UI 上任何硬编码金币数字都视为 Bug。

### 17.1 产出（Earning）

| 渠道 | 公式 | 上限 | 说明 |
|---|---|---|---|
| 完成待办 | `基础 20 币 × 时长系数 × 质量系数` | 每日 10 条计入 | 时长系数见下 |
| 完成自由专注（无关联待办） | `基础 20 币 × 时长系数 × 质量系数 × 0.8` | 每日 5 次计入 | 轻微折扣，鼓励关联待办 |
| 锁机 | `12 币/小时 × 实际完成分钟 / 60` | 每日 8 小时 | 最小结算单位 5 分钟，< 5 分钟不计 |
| 连续锁机加成 | 同一天内第 2 段 +10，第 3 段 +20，第 4 段起 +20 | 每日最多 3 次加成 | 防止刷时长 |
| 健身打卡 | +10 | 每日 1 次 | |
| 健身项目记录 | +5/项 | 每日 3 项 | |
| 饮食记录 | 首次记录 +5；三餐齐全 +10（替换而非叠加） | 每日 1 次 | |
| 记账 | +2/条 | 每日 5 条 | 与金额无关 |
| 里程碑（连续打卡 3/7/14/30 天） | +15 / +40 / +80 / +200 | 每档仅一次 | |
| 准时加成 | 在计划时间 ±2 分钟内开始 +10 | 每日 5 次 | 奖励「不拖延」本身 |

**时长系数（按计划时长）**

| 计划时长 | 系数 |
|---|---|
| ≤ 15 分钟 | 0.6 |
| 16–30 分钟 | 1.0 |
| 31–60 分钟 | 1.5 |
| 61–120 分钟 | 2.0 |
| > 120 分钟 | 2.3（封顶） |

**质量系数（按违规占比与完成度）**

| 条件 | 系数 |
|---|---|
| 完成度 ≥ 100% 且违规 0 秒 | 1.2 |
| 完成度 ≥ 80% 且违规占比 < 10% | 1.0 |
| 完成度 ≥ 50% | 0.7 |
| 完成度 < 50% | 0.4 |
| 中途放弃（未消耗配额，主动结束） | 0.2 |
| 违规占比 > 20% | 在上述结果上 **× 0.5** |
| 消耗配额强行退出 / 越界退出 | **收益归零** |

> ⚠️ **准时加成的前提是「真的开始了」**：`本次跳过` 虽然可能发生在计划时刻，但用户并没有进入这次专注，
> 因此**不给准时加成**（`isPunctual && exitKind !== 'SKIP'`）。
> 否则会出现「跳过（20 × 0.2 + 10 = 14 币）比认真做半小时（20 币）只少一点」的荒谬激励。
> 这条是实现在 M4 阶段发现的规则漏洞，已回写本文档。

**算例校验**（必须写进单测）

> ⚠️ 本表最初有两处算错，已在实现阶段由单测发现并修正（2026-02-14）。
> 教训：**完成度与违规占比要同时看**——违规高会把完成度从「好档」压回「半档」，然后还要再吃一次 ×0.5。

| 场景 | 计算 | 结果 |
|---|---|---|
| 45 分钟、零违规、准时、关联待办 | `20 × 1.5 × 1.2 + 10` | **46 币** |
| 25 分钟、违规 8%、完成 100% | `20 × 1.0 × 1.0` | **20 币** |
| 60 分钟、违规 25%、完成 90% | 完成度 0.9 因违规 25% 不满足「<10%」→ 落 0.7 档；违规 >20% 再 ×0.5 → 质量系数 0.35<br>`20 × 1.5 × 0.35 = 10.5` | **11 币** |
| 锁机 90 分钟 | `12 × 1.5` | **18 币** |
| 一天理想情况 | 专注 `46 + 46` + 锁机 `18` = **110 币**（纯专注/锁机）<br>再叠加健身打卡 10 + 三餐齐全 10 + 3 条记账 6 = **136 币** | **136 币** |
| 自由专注（未关联待办）30 分钟、零违规 | `20 × 0.8 × 1.0 × 1.2 = 19.2` | **19 币** |
| 每日产出上限兜底 | 已产出 395 币，本次应得 46 币 → 只入账 5 币并标记 `capped` | **5 币** |

### 17.2 消耗（Sinking）

| 类别 | 商品示例 | 价格区间 | 效果 |
|---|---|---|---|
| 食物 | 苹果 / 便当 / 蛋糕 / 火锅 | 30 / 60 / 120 / 260 | 饱食度 +10 / +25 / +50 / +100；部分附带心情 +N |

### 17.3 防通胀与防作弊

| 机制 | 规则 |
|---|---|
| 每日产出上限 | 硬上限 **400 币/天**（远超正常值，仅作兜底）；超过部分不计，并记录异常日志 |
| 服务端结算 | 所有入账走服务端函数；客户端仅做乐观显示，服务端返回为准并纠正本地值 |
| 离线补算 | 离线记录带客户端时间戳入队，联网后补算；单次补算 > 200 币时标记为「待复核」并延迟入账 |
| 时间异常 | 检测 `Date.now()` 与 `performance.now()` 单调时钟偏差、以及服务端时间差；偏差 > 60 秒则该段会话收益减半并提示 |
| 时长异常 | 单次会话时长 > 8 小时视为异常，需用户在统计页手动确认后才入账 |
| 重复提交 | 每条记录带 UUID，服务端幂等键去重 |
| 金币不得为负 | 罚款扣至 0 为止，不产生负债 |
| 动态定价（开关） | 可选：当全站人均持有金币 > 1500 时，装扮价格 ×1.15（默认关闭，仅保留能力） |

## 18. 名词表（Glossary）

|---|---|---|
| 待办项 | Task | 一条「时间 + 事件 + 预计时长」的计划 |
| 待办集 | TaskSet | 某一天的全部待办项集合 |
| 专注会话 | FocusSession | 一次专注模式的完整过程，含开始/结束时间、违规、收益 |
| 锁机会话 | LockSession | 一次锁机模式的完整过程 |
| 有效时长 | EffectiveDuration | 专注总时长减去违规暂停累计时间 |
| 违规 | Violation | 约束状态下切走窗口/失焦/退出全屏的行为；累计 ≥ 30 秒才算违规 |
| 配额 | Quota | 可无损退出约束状态的次数。专注：每日 1 + 每月累计 5；锁机：每月 5 |
| 本次跳过 | Skip | 到点时的例外处理，不耗月配额，扣 10 币，每日上限 2 次 |
| 越界退出 | Breach | 配额用尽后仍强行退出，触发重罚 |
| 质量系数 | QualityFactor | 由完成度与违规占比决定的收益乘数 |
| 白名单 | Allowlist | 约束状态下仍允许运行的进程/网站集合 |
| 系统豁免 | SystemExempt | 内置不可删的必需进程（explorer、dwm、输入法、无障碍工具等） |
| 软约束 | SoftRestraint | `[Web]` 模式：全屏 + 违规检测 + 惩罚，不能真正阻止其他应用 |
| 硬约束 | HardRestraint | `[原生]` 模式：桌面增强包真实拦截非白名单进程 |
| 桌面增强包 | Companion | 可选的 Windows 原生伴侣进程，通过本地 WS 与网页通信 |
| 演示模式 | DemoMode | 注入 7 天样例数据的只读展示模式，用于向他人展示 |
| 自然日边界 | DayBoundary | 本地时间 04:00，凌晨 4 点前算前一天 |
| 蔫状态 | Wilting | 宠物因越界惩罚进入的低落状态，持续 30 分钟 |
