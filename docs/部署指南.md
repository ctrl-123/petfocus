# 部署指南

> 目标：把「自律岛」部署成一个**可以贴在简历上的公开链接**，月支出 **0 元**。
>
> 本文只写**已经过验证**的步骤。凡是我无法验证的（需要你登录账号的部分），
> 都明确标注为「需要你操作」。

## 当前采用：GitHub Pages（已验证可用的主路径）

**为什么不用 Vercel**：Vercel 注册强制要求手机短信验证，而它的风控（Twilio）对大量号码失败
——官方社区里满是「收不到验证码 / 号码被封锁 12 小时 / 需要人工客服介入」的求助帖。
GitHub Pages 不需要任何额外账号与手机验证，因为仓库本来就在 GitHub 上。

**站点地址**：`https://ctrl-123.github.io/petfocus/`

### 一次性设置（必须，只需做一次）

**Settings → Pages → Build and deployment → Source → 选 `GitHub Actions`**

> ⚠️ **不要点下面的 `Static HTML` / `Jekyll` 预设按钮。** 那是给「把 HTML 直接提交到分支」
> 的旧方式用的，会与本仓库的 Actions 工作流冲突。

### 之后每次部署

推送到 `main` 即自动部署（`.github/workflows/deploy-pages.yml`）。

### 三个已经踩过的坑（改 workflow 前必读）

| 坑 | 现象 | 原因与修法 |
|---|---|---|
| **pnpm 版本两处指定** | 工作流 **10 秒内**失败 | `package.json` 已有 `packageManager: "pnpm@9.15.4"`，若 workflow 里再写 `pnpm/action-setup` 的 `version:`，会以 `Multiple versions of pnpm specified` 直接退出。**只留 `packageManager` 一处。** |
| **Pages 站点不存在** | `configure-pages` 报 `Get Pages site failed ... Error: Not Found` | 创建 Pages 站点是**仓库管理级操作**，自动的 `GITHUB_TOKEN` 在任何 `permissions` 下都无法执行。`enablement: true` 也不行，只会换成 `Resource not accessible by integration`。**只能靠上面那次网页设置。** 设置后若仍失败，点 `Re-run all jobs` 即可。 |
| **子路径 404 白屏** | 线上白屏，本地正常 | Pages 部署在 `/petfocus/` 子目录下，构建必须传 `BASE_PATH=/petfocus/`。这个错误本地**永远复现不了**。守卫：`node tools/check-build-paths.mjs /petfocus/` |
| **Node 版本不一致** | 本地测试全过、CI 挂 | 测试脚本依赖 `--experimental-strip-types` 与 `--test` 的 glob 行为，Node 22/24 之间有差异。workflow 与本机统一用 24。 |

### 本地复现 CI 的检查

```bash
pnpm install --frozen-lockfile    # 验证 lockfile 与 package.json 同步
pnpm verify                       # typecheck + lint + 1297 项测试 + 覆盖率

# 验证两种部署目标的资源路径
pnpm build && node tools/check-build-paths.mjs /
BASE_PATH=/petfocus/ pnpm build && node tools/check-build-paths.mjs /petfocus/
```

## 备选：Netlify Drop（最快拿到链接，但链接是临时的）

不需要注册、不需要 Git：

1. `pnpm build`（**不要**设 `BASE_PATH`，Netlify 部署在根路径）
2. 打开 <https://app.netlify.com/drop>
3. 把 `apps/web/dist` 文件夹**拖进去**
4. 立刻得到一个形如 `https://random-name-123.netlify.app` 的链接

适合临时演示。要长期保留需注册账号（可能也要手机验证）。

## 备选：Vercel（当前受手机验证阻塞）

如果哪天 Vercel 的短信验证能通过，仓库根目录的 `vercel.json` 已经配好：

- 构建命令 `pnpm --filter @petfocus/web build`
- 安装命令 `pnpm install --frozen-lockfile`
- 输出目录 `apps/web/dist`
- SPA 回退、静态资源长缓存、`sw.js` 不缓存、基础安全头

Vercel 部署在**根路径**，因此**不要**设 `BASE_PATH`。

### 部署后必查 4 项（任何平台都适用）

| 检查项 | 怎么看 | 期望结果 |
|---|---|---|
| 首页能开 | 打开根链接 | 出现「自律岛」与左侧导航 |
| 深链接不白屏 | 访问 `/anything` | 仍显示应用（Pages 需要 404.html 兜底，见下） |
| **演示模式可用** | 打开 `?demo=1` | 顶部黄色提示，且各处都有数据 |
| PWA 可安装 | 地址栏右侧出现安装图标 | 可安装；断网后仍能打开 |

**演示模式是关键**：评审者不需要你自己先录入数据，点开 `?demo=1` 就能看到
连续 12 天健身打卡、两周专注记录、20 多笔账、7 天饮食记录。

> ⚠️ GitHub Pages 对未知路径返回 `404.html`。本项目是 SPA，深链接需要兜底。
> 当前只用到 `?demo=1` 这种查询串（不是路径），所以不受影响；
> 若以后引入 History 路由，必须额外生成 `404.html`。

## 可选：Supabase Edge Functions（v0.2）

> **不做这一步，应用也能完整使用。** 缺的只是：
> 1. 服务端权威的金币/配额结算（防"改系统时间刷金币"）
> 2. AI 营养估算回退（本地库未命中时）
>
> 因为架构是**本地优先**：业务数据本来就在本机，
> 结算服务不可用时网页仍完整可用，只有结算进队列等联网。
> 这正是 ADR-011 里"免费版被暂停也不影响使用"的原因。

### 需要你提供的三项

| 项 | 从哪里拿 | 用途 |
|---|---|---|
| `SUPABASE_URL` | Supabase 项目 Settings → API | 前端调用地址 |
| `SUPABASE_ANON_KEY` | 同上 | 公开的匿名 key（**可以**进前端） |
| `service_role` key | 同上 | **只能放 Edge Function 的环境变量，绝不进前端** |

### 必须遵守的服务端规则（技术设计 5.6 / AGENTS.md 第 4 节）

- 服务端只允许 **4 张表**：`devices` / `coin_ledger` / `quota_ledger` / `ai_nutrition_cache`
- **启用 RLS 但不建任何 policy**（默认全拒），并撤销 `anon` / `authenticated` 的表权限
- 只有 Edge Function 用 `service_role` 访问数据库
- **绝不上传业务数据**（待办、会话、宠物、记账、饮食），只传结算摘要

### AI 营养估算的成本护栏（ADR-011）

- 顺序必须是：**本地食物库（502 条，已实现）→ 服务端缓存 → 每设备每日 ≤ 20 次 → 全局每日 ≤ 200 次**
- 超限返回 `AI_UNAVAILABLE`，前端**回退到手工录入**（已实现）
- 不配置 LLM Key 时完全不会产生费用

## 已知限制（如实说明，不要藏着）

| 限制 | 说明 |
|---|---|
| **网页无法阻止其他程序启动** | 这是浏览器能力边界。网页端是「软约束」：全屏接管 + 离开检测 + 收益惩罚。真实拦截需要可选的 Windows 桌面增强包（v0.2） |
| **服务端结算未接入** | 当前金币与配额是本地乐观记账。改系统时间不能刷币（单调时钟计时），但改 IndexedDB 可以。这在 ADR-010 里被明确接受并如实公示 |
| **AI 营养估算未接入** | 本地库未命中时走手工录入，不猜数值 |
| **Live2D 未接入** | 宠物当前是 SVG 绘制（见 `docs/spikes/live2d-model-selection.md`）。界面与文档都没有声称是 Live2D |
| **导出的备份是明文 JSON** | 包含记账与饮食记录。设置页已提示「请自行妥善保管」 |

## 本机特有：Git 连不上 GitHub（Steam++ 加速器）

本机装了 **Steam++（Watt Toolkit）**，它修改 hosts 把 `github.com` 指向 `127.0.0.1`
并在本地 443 做 TLS 中间人，用自签证书替换真实证书。由此导致：

- schannel 后端：`CRYPT_E_NO_REVOCATION_CHECK (0x80092012)`
  （`http.schannelCheckRevoke=false` 在 Git for Windows 2.56 上**不生效**）
- openssl 后端：`unable to get local issuer certificate (20)`，因为 Git 自带 CA 包不含它

**修法**：运行 `node tools/setup-git-tls.mjs`
—— 导出 SteamTools 根证书 → 转 PEM → 追加进 Git 的 CA 包（121 → 122 张）→ 切 openssl 后端。

⚠️ 该证书**有效期至 2027-05-29**。到期或加速器换证书后若又连不上，重跑该脚本即可（幂等）。

推送用 `push.cmd`（由 `node tools/gen-push-cmd.mjs` 生成）。
